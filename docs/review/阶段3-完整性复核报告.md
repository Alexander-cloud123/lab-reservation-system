## 六、两项「看似缺失、实为设计如此」

### 6.1 `GET /api/config/booking-rules` 没有页面入口

其调用点在路由守卫（`web/src/router/index.js`：进入受保护路由前拉取一次预约规则并缓存），属**全局前置**，本就不产生页面级入口。规则来源以后端 `Constants` 为唯一真源、前端不硬编码，符合「禁止硬编码」规范。

### 6.2 消息通知中心不调任何接口

消息由 `GET /api/reservation/mine` 的结果**派生**（待审核 / 已驳回含备注），已读状态存 localStorage。这是需求设计文档第 59 行明文指定的实现（「消息通知中心｜冲优｜由预约表状态动态生成，已读状态存 localStorage」），**不是后端缺口**，故不计入完整性风险。
