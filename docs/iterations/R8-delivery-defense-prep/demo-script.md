# R8 标准演示脚本（核心业务闭环）

> 适用：实训/答辩现场演示。演示数据全部使用数据库**初始基线**（详见「测试数据说明」），禁止新增或修改基线数据；演示中产生的写操作在「恢复基线」小节统一还原。
> 前置：Docker 容器 `reservation-mysql` 运行中；后端启动（交付配置，`ai.enable=false`）；前端 `npm run dev` 访问 http://localhost:5173。
> 环境命令见 `startup-guide.md`。

## 演示流程总览（先核心闭环，AI 做压轴）

```
登录（学生）→ 教室浏览/筛选 → 手动预约提交 → 冲突检测演示 → 我的预约/取消（1 小时限制）
→ 管理员登录 → 审核（通过/驳回/批量）→ 数据看板 → 日历总览
```

（AI 推荐 / 快速预约 / 合规校验 / 助手见 `docs/ai-demo-script.md`，作为压轴演示。）

|---|---|
| 操作位置 | 学生端 · 我的预约页 |
| 数据用例 | zhangsan（id=2）基线预约：id=1（待审核，今天 14:00-16:00）、id=3（已通过，明天 09:00-11:00）、id=6（已通过，前天）、id=10（已驳回，4 天前） |
| 操作 | ① 查看状态标签页（待审核/已通过/已驳回/已取消）与今日置顶；② 对 id=3（明天开始，>1 小时）点「取消」→ 二次确认 → 状态变已取消；③ 说明「开始前 1 小时内不可取消」规则：对今天 15:00 开始、当前时间不足 1 小时的已通过预约（如 lisi 的 id=2），取消按钮禁用并提示 |

### 恢复基线（演示结束后必须执行）

演示过程中可能产生的写操作及还原方式（按实际执行路径执行对应项）：

```powershell
# 1) 删除演示新增的预约（id>13 均为演示产生）
docker exec reservation-mysql mysql -uroot -proot reservation -e "DELETE FROM reservation WHERE id>13;"

# 2) 还原被取消的预约（示例：第 5 步取消了 id=3 → 还原为已通过）
docker exec reservation-mysql mysql -uroot -proot reservation -e "UPDATE reservation SET status=1, audit_remark='同意', auditor_id=1 WHERE id=3;"

# 3) 还原被审核的记录（示例：第 7 步把 id=7 驳回 → 还原为待审核；批量操作同理按清单还原）
docker exec reservation-mysql mysql -uroot -proot reservation -e "UPDATE reservation SET status=0, audit_remark=NULL, auditor_id=NULL, audit_time=NULL WHERE id IN (1,7,13);"

# 4) 复核基线（期望：reservation=13、user_favorite=6、sys_user=5、ai_config=5）
docker exec reservation-mysql mysql -uroot -proot reservation -e "SELECT (SELECT COUNT(*) FROM reservation) AS r,(SELECT COUNT(*) FROM user_favorite) AS f,(SELECT COUNT(*) FROM sys_user) AS u,(SELECT COUNT(*) FROM ai_config) AS a;"
```

> 若演示全程未执行写操作（仅读路径），只需执行第 4 步复核。
> PowerShell 向 docker exec 传中文会 GBK 乱码，涉及中文值的语句需用 `HEX CONVERT(0x… USING utf8mb4)`，本脚本恢复语句均为 ASCII 值，可直接执行。
