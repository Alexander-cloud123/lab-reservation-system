## 5. 机器代理与既有自动化的关系

- 本脚本**不并入** `npm run test:e2e` 回归（不改变 17 spec / 120 例口径）；它是验收取证的独立工具。
- B3/B4 的机器证据直接引用回归 spec 的执行结果，避免重复造数。
- 脚本内 AI 全部 mock：即使 `AI_ENABLE=false` 也能完整验证前端播报链路（零额度消耗）。
- 本轮最终代码回归：**Chromium 120/120、Edge 120/120**（2026-11-07）；`npm run lint` 与 `npm run build` 均通过。
- 复跑注意：E2E 前须清理库内 `E2E%` 预约 / `e2e%` 账号与 Redis `auth:login:fail:*`、`auth:login:lock:*`。
  本轮实测：残留数据会让 `40-rules` 的造数时段被判冲突，残留失败计数会让「不存在的账号」用例命中锁定提示——
  两者都是**测试数据污染**，不是代码缺陷（清理后 120/120 全过）。
