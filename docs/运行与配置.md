# 运行与配置

本文件收纳 README 中较细的运行配置项：环境变量、AI 模块、Redis 开关语义、端口与测试变量。
README 只保留「怎么最快跑起来」，细节以本文件为准。

## 1. 环境变量

后端配置采用 `${ENV:default}` 占位写法，全部可在不改动配置文件的条件下覆盖（来源：[application.yml](../server/src/main/resources/application.yml)）。

| 变量 | 默认值 | 用途 | 是否必填 |
|------|--------|------|----------|
| `MYSQL_URL` | `jdbc:mysql://localhost:3306/reservation?...` | 数据库连接串 | 本机容器映射 3307，需覆盖 |
| `MYSQL_USERNAME` | `root` | 数据库账号 | 否 |
| `MYSQL_PASSWORD` | `root` | 数据库密码 | 否 |
| `REDIS_HOST` | `127.0.0.1` | Redis 主机 | 否 |
| `REDIS_PORT` | `6379` | Redis 端口 | 本机容器映射 6380，需覆盖 |
| `REDIS_PASSWORD` | 空 | Redis 密码 | 否 |
| `REDIS_DATABASE` | `0` | Redis 库序号 | 否 |
| `REDIS_ENABLE` | `true` | Redis 总开关；置 `false` 后无单点会话、无缓存（登出 / 改密等撤销仍由 `token_version` 生效），启用但连接异常时会话校验 fail closed（401） | 否 |
| `MYBATIS_LOG_IMPL` | `org.apache.ibatis.logging.stdout.StdOutImpl` | SQL 日志实现；`docker-compose.yml` 已固定为 `NoLoggingImpl`，置 `nologging` 可关闭 | 否 |
| `KNIFE4J_ENABLE` | `true` | 接口文档总开关（同时控制 `/doc.html` 与 `/v3/api-docs`）；compose 固定为 `false` | 否 |
| `CORS_ALLOWED_ORIGINS` | `*` | 跨域白名单（逗号分隔）；compose 收敛为 `http://127.0.0.1:<WEB_PORT>,http://localhost:<WEB_PORT>,http://127.0.0.1:5173,http://localhost:5173`（含 Vite dev / E2E） | 否 |
| `SPRING_PROFILES_ACTIVE` | 空 | 激活的 profile；compose 固定为 `prod`，让 `JwtSecretGuard` 强制校验密钥 | 否 |
| `AI_ENABLE` | `false`（yml）/ `true`（compose） | AI 静态总开关；容器演示默认开启，裸 jar 与 CI 保持关闭 | 否 |
| `AGNES_API_KEY` | 空 | Agnes 上游密钥，**仅环境变量注入，禁止硬编码**；不配置时自动使用本地规则，需要真实 Agnes 上游时才填写有效密钥 | 否（真实上游必填） |
| `JWT_SECRET` | 无（本机无 profile 时回退开发默认值） | Token 签名密钥，**compose 必填**：至少 32 字节随机值，缺失/为空/沿用开发默认值时启动失败 | compose 必填 |

前端与 E2E 侧变量（来源：[vite.config.js](../web/vite.config.js)、[playwright.config.js](../web/playwright.config.js)）：

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `VITE_API_TARGET` | `http://localhost:8080` | Vite 开发代理的后端目标 |
| `E2E_API_PORT` | `8080` | E2E 后端端口（同时作为前端代理目标） |
| `E2E_API_BASE` | `http://127.0.0.1:${E2E_API_PORT}` | E2E 启动探活地址 |
| `E2E_API_TARGET` | `http://localhost:${E2E_API_PORT}` | E2E 期间的后端代理目标 |
| `E2E_WEB_PORT` | `5173` | E2E 前端端口 |

截图与无障碍脚本的变量（`web/scripts/`）：

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `CAPTURE_BASE` | `http://127.0.0.1:5173` | 截图脚本访问的前端地址 |
| `CAPTURE_API` | `http://127.0.0.1:8080` | 截图脚本登录用的后端地址 |

## 2. AI 模块

**双开关，默认值分层**（关闭后不影响核心系统运行）：

| 运行方式 | 静态开关 `ai.enable` | 数据库开关 `ai_config.ai_enable` | 结果 |
|----------|----------------------|-----------------------------------|------|
| `docker compose up -d`（演示） | compose 默认注入 `AI_ENABLE=true` | 种子 `true` | **默认开启**，无需手动操作 |
| 裸 `java -jar` / `mvn spring-boot:run` | `application.yml` 默认 `false` | 库内值 | 默认关闭（零依赖、确定性） |
| 单测 / CI（server-ci、stack-smoke） | 工作流显式 `AI_ENABLE=false` | — | 固定关闭，不碰上游 |

- 静态总开关：`application.yml` 中 `ai.enable`（默认 `false`，可被环境变量 `AI_ENABLE` 覆盖）。
- 数据库开关：`ai_config` 表的 `ai_enable`。两者同为 `true` 时 AI 入口与本地规则能力可用；只有需要真实 Agnes 上游时才必须配置有效 `AGNES_API_KEY`。
- 无密钥时即便两开关都开，也会自动降级为本地规则并在界面标注，不会阻断业务；`AI_ENABLE=true` 本身不要求必须配置密钥。

切换与补齐：

```powershell
# 关闭演示 AI（立即生效，只改 ai_config 一行）
pwsh server/scripts/ai-switch.ps1 -Off

# 重新开启 / 老数据卷补齐（ai_config.ai_enable 仍为 false 时跑一次）
pwsh server/scripts/ai-switch.ps1

# 彻底关闭（静态层）：.env 改 AI_ENABLE=false 后 docker compose up -d api（restart 不会重读环境变量）
```

> `ai-switch.ps1` 会顺带清 `cache:ai:*` 并等 5 秒开关缓存过期，最后打印登录接口下发的 `aiEnabled`。
> 存量数据卷升级提示：`init_db.sql` 的种子改动只影响新建库；沿用旧 external 卷的部署需跑一次 `ai-switch.ps1`。

**悬浮球 / AI 入口不出现的排查顺序**：

| 现象 | 先查什么 | 处理 |
|------|----------|------|
| 学生端右下角没有悬浮球 | 两个开关是否都开 | `pwsh server/scripts/ai-switch.ps1`，看输出 `aiEnabled=True` |
| 打印 `aiEnabled=False` | `AI_ENABLE`（静态）是否仍为 false | 改 `.env` 后重建容器：`docker compose up -d api`（`restart` **不会**重读环境变量） |
| 两个开关都开、刷新仍无球 | 浏览器 localStorage 旧值 `reservation_ai_enabled=false` | 刷新即可（服务端探测优先）；仍无则清站点数据后重新登录 |
| 只有管理员端没有 | 设计如此 | 悬浮球只挂载在学生布局，管理员端不显示 |

> 注意：`init_db.sql` 种子现为「默认开启」。`docker compose down -v` 或重建数据卷后会重新导入种子（`ai_enable=true`），无需手动开；只有**沿用旧数据卷**（种子改动前创建）时才需跑一次 `pwsh server/scripts/ai-switch.ps1` 补齐。仅重启容器不受影响。

运行时行为：

- 接入国内节点 `https://api.agnes-ai.cn/v1`，模型 `agnes-3.0-flash`，密钥经 `AGNES_API_KEY` 注入，前端零接触。
- 单请求 **60 秒绝对预算**（`AiRequestDeadline`，流式帧间不重置）；超时、报错、限流、密钥缺失、输出不合法均降级为**本地规则模拟模式**，返回体带降级原因，不阻断业务。
- **只读不写**：AI 仅查询数据、解析需求、给出建议，所有业务操作必须由用户手动确认；生成内容前端统一标注「AI 生成，仅供参考」。
- 结果缓存**只写成功分支**，降级结果永不写入，避免把本地规则固化成模型结果。

流式契约：

- 智能问答 `POST /api/ai/chat?stream=true` 为真流式输出（打字机体验），支持 Markdown 渲染、会话内多轮上下文（不持久化）、发送中停止生成。
- 推荐 / 预约解析 / 合规校验三个接口在 `?stream=true` 时输出结构化进度事件流 `meta → phase → result → done`，其中 `result` 与非流式的 `data` 完全同构。
- 不带 `?stream=true` 时，全部接口保持原有 `Result<VO>` 契约不变。

## 3. Redis 开关语义（摘要）

完整说明见 [Redis 加分项接入说明](Redis加分项接入说明.md)。

- `REDIS_ENABLE=true` + 连接正常：单点会话、登录状态 60 秒快照、看板/教室列表短缓存；
- `REDIS_ENABLE=true` + 连接异常：缓存回源、会话校验 **fail closed（401）**，撤销仍由 `token_version` 保证；
- `REDIS_ENABLE=false`：完全无状态 JWT，无单点会话与缓存；登出/改密/重置/禁用仍持久撤销。

## 4. 本地端口约定

| 服务 | 容器方式 | 本地开发 |
|------|----------|----------|
| MySQL | `127.0.0.1:3307` | 同左（用 `MYSQL_URL` 覆盖默认 3306） |
| Redis | `127.0.0.1:6380` | 同左（用 `REDIS_PORT` 覆盖默认 6379） |
| 后端 API | `127.0.0.1:8080` | `127.0.0.1:8080` |
| 前端 | `127.0.0.1:8088`（nginx 静态） | `127.0.0.1:5173`（Vite dev） |
| 接口文档 | `http://localhost:8080/doc.html` | 同左 |

端口被占用时：后端可用 `--server.port=8081`，并给 E2E 设置 `E2E_API_PORT=8081`；前端用 `npm run dev -- --port 5174`。
