**额度现实（如实记录）**：该免费账号上游限流远紧于文档记载的 ~10 次/分钟。本轮实测：10 秒间隔 → 4 次中 3 次 429；60 秒间隔 → 4 次中 1 次 429、1 次超时；**100 秒间隔 → 4/4 全部真实成功、零降级**。降级本身按设计自动兜底（页面不报错），不属于缺陷；验收脚本据此采用重试与长间隔，并以「每端点最终真实成功 + NO_KEY=0」为硬判定。

3. **Redis 故障恢复窗口**：撤销清理为 **best-effort**。Redis 不可用 / 超时导致删除状态快照失败时，故障期间受保护接口仍 **fail-closed（401）**；但 Redis 恢复后，该快照剩余 TTL（≤60s）内版本校验可能读到旧值，**撤销后的旧 Token 在该窗口内仍可能被接受**（窗口结束后快照过期、回源数据库即 401；不随会话 Key 的 24h TTL 放大）。本轮已修正口径：`docs/Redis加分项接入说明.md` §3 表、§4「已知边界」、§5、§6.2，`docs/演示脚本.md` §5.5 / §5.6，以及 `AuthInterceptor` / `RedisCache` 注释统一为「删除成功即即时生效，删除失败 ≤60s 有界窗口」。不改代码：严格零窗口需拦截器每请求回源查库，会推翻 60s 缓存收益。
4. **AI 验收依赖账号额度**：真实调用结论依赖该密钥的可用额度；本次已实测通过，但演示时仍建议按 `docs/演示脚本.md` 的限流纪律操作。
