# 依赖安全审计（2026-11-26）

> 范围：`web/package.json` 与 `web/package-lock.json`。本文记录本次 npm 审计、已应用的补丁及剩余项的实际利用面；不把版本较旧直接等同于存在已证实漏洞，也不宣称 npm audit 已清零。

## 1. 审计方式

本机默认 npmmirror 镜像不实现 `/-/npm/v1/security/*`，因此审计显式使用 npm 官方 registry：

```bash
cd web
npm audit --json --registry=https://registry.npmjs.org
npm audit fix --registry=https://registry.npmjs.org
npm ls markdown-it follow-redirects source-map-js postcss-selector-parser --depth=2
```

首次审计报告 **10 个受影响包（6 high / 4 moderate）**。先执行 `npm audit fix --dry-run`，确认无需大版本升级的修复范围后才应用补丁。

## 4. 后续规则

1. 拉取依赖或发布前使用官方 registry 复跑审计；镜像返回 `NOT_IMPLEMENTED` 不代表没有漏洞。
2. 新 advisory 先判断运行环境、组件是否使用、输入是否可信，再决定补丁、缓解或升级；不直接执行 `npm audit fix --force`。
3. 大版本升级必须单独评审并跑完整回归，不与发布素材、文档修改混在同一提交。
4. 本文件只覆盖前端 npm 依赖，不构成后端 Maven 依赖无漏洞的结论；后端 SCA 作为后续维护项单独执行。
