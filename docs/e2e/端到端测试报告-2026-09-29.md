- 列表类断言以「接口响应体」为期望来源（先 `waitForResponse` 再断言渲染），规避重渲染竞态。

- AI 用例采用「浏览器层拦截 `/api/ai/*`」策略（`helpers/ai.js`），**真实模型零调用**；关闭态由 localStorage `reservation_ai_enabled=false` 短路，不发探测请求。

### 缺陷 #5 根因分析（AI 推荐必然降级）

**定位**：[AiRecommendServiceImpl.java](file:///c:/Users/72797/Course/reservation-system/server/src/main/java/com/example/reservation/ai/service/impl/AiRecommendServiceImpl.java)

| 环节 | 位置 | 内容 |
|---|---|---|
| **客户端调用模式（真因）** | [AgnesClient.java#L129-L133](file:///c:/Users/72797/Course/reservation-system/server/src/main/java/com/example/reservation/ai/config/AgnesClient.java#L129-L133) | `jsonMode=true` 时强制 `response_format={"type":"json_object"}` —— **结构化输出模式要求顶层必须是 JSON 对象**，与下方 Prompt 要求直接冲突 |
| Prompt 要求（与上冲突） | [L50-L53](file:///c:/Users/72797/Course/reservation-system/server/src/main/java/com/example/reservation/ai/service/impl/AiRecommendServiceImpl.java#L50-L53) | 「只能从候选教室的 classroomId 中选择，输出 **JSON 数组**：`[{"classroomId":数字,"reason":"一句话理由"}]`」 |
| 解析器容错 | [L263-L270](file:///c:/Users/72797/Course/reservation-system/server/src/main/java/com/example/reservation/ai/service/impl/AiRecommendServiceImpl.java#L263-L270) | `JsonNode arr = root.isArray() ? root : root.path("recommendations");` — **仅兼容「根数组」与 `{recommendations:[...]}` 两种形态** |
| 模型实际输出 | 日志 | `{"classroomId": 2, "reason": "容量80人且全天空闲，兼具多媒体功能与较高通用性，适合中等规模课程灵活使用。"}` — **单对象**，非数组、非 `recommendations` 键 |
| 结果 | [L114-L125](file:///c:/Users/72797/Course/reservation-system/server/src/main/java/com/example/reservation/ai/service/impl/AiRecommendServiceImpl.java#L114-L125) | 两个分支均不命中 → `arr.isArray()` 为 false → `return null` → 走规则打分降级 |

**观测结论**：
1. **不是模型不可用**——模型连通、额度正常、返回内容语义合理（唯一问题是不听「数组」指令，且只挑了 1 间而非 3 间）。
2. **100% 降级**：2/2 次真实调用全部降级，返回的 `recommendations[].reason` 是规则模板文案（如「明日全天空闲，您常约的实验楼，符合您常约的类型」），而非模型生成。
3. **降级对前端不可观测**：降级分支执行 `vo.setMessage(resp.reason())`，但 `resp.ok()` 为真时 `resp.reason()` 为空 → 实测 `message=""`。前端因此**无法区分「真实模型结果」与「规则降级结果」**——答辩现场看起来一切正常，实际展示的是本地规则。

### 同类可观测性问题修复（#6，已完成 · 2026-09-29）

`AiParseServiceImpl` / `AiChatServiceImpl` / `AiComplianceServiceImpl` 的降级分支原本是 `vo.setMessage(resp.reason())`，与 #5③ 完全同因：`resp.ok()=true` 但模型输出解析失败时 `reason` 为 `null` → `message` 为空 → 降级不可观测。

**修复**（3 个服务同口径，与 #5③ 一致）：

```java
String degradeReason;
if (resp.ok()) {
    XXXVO vo = parseModelOutput(resp.content());
    if (vo != null) { vo.setEnabled(true); return vo; }
    log.warn("...模型输出不合法，切换降级：{}", resp.content());
    degradeReason = AiConstants.AI_OUTPUT_INVALID_MESSAGE;   // 模型有返回但结构不合法
} else {
    degradeReason = resp.reason();                          // 限流/密钥缺失/服务异常
}
...
```

### 6. 残留口径修正（排查结论 · 2026-10-01）

第 1/3/5 节清理时观测到的残留条数（48 / 54 / 55）**明显高于"单次运行的期望写入量"**，曾据此怀疑"每个造数用例写入 2 行"。该怀疑已被排查**推翻**，结论如下：

**结论：E2E 套件不存在重复写入。一次 Playwright 调用只执行一次，每个造数用例只写 1 行。**

| 验证实验 | 观测 | 结论 |
|---|---|---|
| 受控窗口·单用例（沙箱开） | 日志增量 `INSERT = 1`、行数 +1 | 单次调用写 1 行 |
| 受控窗口·单用例（沙箱关） | 日志增量 `INSERT = 1`、行数 +1 | 同上 |
| `globalSetup` 标记法·单用例 | 标记 **1** 行（每次调用 `globalSetup` 恰好执行一次） | 命令只执行一次 |
| **`globalSetup` 标记法·完整 30-ai（10 用例）** | 标记 **1** 行、`INSERT = 3`、行数 14→17、10 passed | **一次调用执行一次；3 个造数用例 → 恰好 3 行** |

**排查方法与已排除项**：
- 方法：给 `e2e/global-setup.js` 临时加一行「每次调用追加标记」，用标记行数直接统计执行次数（比读输出可靠）；该临时改动**已还原**，仓库无残留。
