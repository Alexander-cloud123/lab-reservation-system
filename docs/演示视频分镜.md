# 演示视频分镜与录制说明

面向简历投递与作品页展示的两份材料：

| 产物 | 位置 | 用途 |
|------|------|------|
| 41 秒 GIF | `docs/images/demo-walkthrough.gif`（880×550 / 10fps / 6.4MB） | README 顶部「演示」区块，自动播放，30 秒内看到核心链路 |
| 完整版视频（73 秒） | `.devtmp/demo/demo-walkthrough.mp4`（1440×900 / H.264） | GitHub Release 资产，README 提供下载链接；本地不入库 |
| AI 助手思考片段（约 30 秒） | `.devtmp/demo/demo-ai-thinking.mp4`（1440×900 / H.264） | GitHub Release 资产，README「演示」区块链接；本地不入库 |

三份材料都由同一个脚本 `web/scripts/capture-demo-video.mjs` 用 Playwright 驱动真实浏览器录制，页面操作走真实 UI 与真实接口，不拼接截图、不做后期剪辑。

## 一、前置环境

| 依赖 | 要求 |
|------|------|
| 应用栈 | `docker compose up -d` 后：web `http://127.0.0.1:8088`、api `http://127.0.0.1:8080`、MySQL `127.0.0.1:3307`、Redis `127.0.0.1:6380` |
| ffmpeg | 默认读取 `.devtmp/tools/ffmpeg/ffmpeg.exe`；可用 `--ffmpeg` 或环境变量 `FFMPEG_BIN` 指向任意完整构建（需含 `palettegen` / `paletteuse` / `libx264`） |
| Playwright | 已在 `web/` devDependencies（`@playwright/test`），首次运行前 `npx playwright install chromium` |
| 账号 | 种子账号：`zhangsan / 123456`（学生）、`admin / admin123`（管理员） |

本机没有系统 ffmpeg 时，可在工作区取一份静态构建（不入库）：

```powershell
New-Item -ItemType Directory -Force .devtmp\tools | Out-Null
Push-Location .devtmp\tools
npm pack @ffmpeg-installer/win32-x64@4.1.0
tar -xzf ffmpeg-installer-win32-x64-4.1.0.tgz
New-Item -ItemType Directory -Force ffmpeg | Out-Null
Copy-Item package\ffmpeg.exe ffmpeg\ffmpeg.exe
Pop-Location
```

## 二、一键录制

```powershell
# 在 web/ 目录下
npm run demo:gif      # 录 41 秒 GIF，直接写入 docs/images/demo-walkthrough.gif
npm run demo:full     # 录完整版视频，写入 .devtmp/demo/demo-walkthrough.mp4
npm run demo:ai       # 录 AI 助手思考片段，写入 .devtmp/demo/demo-ai-thinking.mp4

# 等价于（可自定义参数）
node scripts/capture-demo-video.mjs --mode=gif --base=http://127.0.0.1:8088 --api=http://127.0.0.1:8080
```

常用参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--mode` | 必填 | `gif` / `full` / `ai`（`ai` 只录 AI 助手片段） |
| `--base` | `http://127.0.0.1:8088` | 页面地址（也可指向 dev server 5173） |
| `--api` | `http://127.0.0.1:8080` | 接口地址，用于造演示数据与登录 |
| `--out` | `.devtmp/demo` | 原始录屏与 mp4 输出目录 |
| `--ffmpeg` | `.devtmp/tools/ffmpeg/ffmpeg.exe` | ffmpeg 可执行文件 |
| `--reset` | `both` | 录制前/后复位数据库：`both` / `before` / `after` / `none` |
| `--encode` | `true` | `false` 时只录 webm，不编码，便于调分镜 |
| `--gif-fps` / `--gif-width` / `--gif-colors` | `12` / `960` / `192` | GIF 首轮编码参数；超过 8MB 会自动降到 `10fps / 128 色 / 880px` 重编 |

## 五、AI 助手思考片段分镜（实测 29.6 秒）

`--mode=ai` 单独录一段 AI 人机交互，用于说明「思考过程不是装饰」：面板里的每一步都是后端真实执行轨迹，计时也是服务端实测耗时。

| # | 段落 | 画面与操作 | 旁白要点 |
|---|------|-----------|----------|
| 0 | 开场（≈2s） | 登录页 + 字幕「AI 助手：真实思考过程、思考计时与等待动画」 | 亮点不是「接了大模型」，而是把等待过程讲清楚 |
| 1 | 登录（fast 登录） | 学生账号进入首页；推荐卡与悬浮球由登录后的一次探测请求拉起 | AI 入口可用性由服务端探测驱动，不信任本地缓存 |
| 2 | 推荐卡（≈10s） | 「AI 为你推荐」Top3：教室、楼栋、容量、推荐理由、来源标注 | 推荐理由由模型生成；降级时来源标注切换为「本地规则结果」 |
| 3 | 打开助手（≈1s） | 点右下悬浮球 → 进入 `/student/ai` 全屏对话页 | 悬浮球只在学生端、且服务端探测开启时出现 |
| 4 | 提问（≈2s） | 输入「我明天有哪些预约？取消预约要注意什么？」并发送 | 自然语言入口，问题经场景闸门后进入真实流水线 |
| 5 | 思考中（≈3s） | 面板三点脉冲 + 逐条步骤：确认范围 → 检索我的预约 → 调用模型生成 → 校验回答 → 汇总；运行中步骤带脉冲，完成步骤显示服务端实测耗时 | `thinking` 事件按真实流水线顺序发出，不是伪造的思维链 |
| 6 | 自动折叠（≈2s） | 首个回答片段到达后，面板收成「已思考 X.X 秒」 | 不打断阅读；折叠后仍保留「命中缓存 / 已降级」等摘要 |
| 7 | 展开回看（≈3s） | 点面板头展开：步骤时间线与推理区；本机模型未返回推理文本时显示「以上为本次处理的实际步骤」 | 每步耗时与推理原文（若上游返回）都可回看，内容固定标注「AI 生成，仅供参考」 |
| 8 | 回答流式 + 收尾（≈4s） | Markdown 逐字出现，停留对话页，底部字幕「AI 生成，仅供参考；所有写操作由用户手动确认」 | 只读不写：AI 不会替用户提交任何预约 |

录制前置（与 GIF / 完整版不同）：

1. **AI 必须开启**：容器部署默认已开（`AI_ENABLE` 默认 true + `ai_config.ai_enable` 种子 true）；未配置密钥时会自动降级为本地规则，片段仍可录，但推荐理由来源标注会变成「本地规则结果」。
2. **清空 AI 缓存再预热推荐**：`ai` 模式先清空 Redis `cache:ai:*`，保证等待动画与逐步轨迹真实出现；再用 `zhangsan` 调一次 `/api/ai/recommend?stream=true` 让 60 秒推荐缓存命中，避免片头空等（日志打印「推荐缓存预热完成（x.xs）」）。
3. **真实模型耗时不可控**：问答段最多等 45 秒，超时会点「停止」并加字幕说明 60 秒预算兜底；想录到完整流式回答，建议在额度充足、上游不排队时重录。
4. **面板头点击可能被滚动拦截**：对话正文会跟随贴底滚动，按坐标点击可能落空；脚本按「合成光标 tap → Playwright 点击 → DOM 点击」三级兜底，日志出现「面板头常规点击失败」属预期降级，展开仍会成功。

## 六、数据可复现设计（任意时刻都能录）

脚本不依赖「录制当天恰好有数据」，每次录制前自动完成三件事：

1. **复位基线**：以 `database/init_db.sql` 重新灌库（13 条预约 / 5 个账号 / 12 间教室），所有预约日期都是 `CURDATE()` 相对日期。
2. **造 2 条待审核**：以 `zhangsan` 在明日对 A301（15:00–16:00）与 B101（16:00–17:00）各提交一条真实待审核预约，供「批量通过」段落使用；提交前先查冲突接口确认空闲。
3. **锚定不可变冲突**：种子预约 `id=3` 是 B101（教室 5）**明日 09:00–11:00 已通过**，因此「明日 09:00–10:00」在任何日期录制都会触发冲突，无需人工挑数据。

录制结束再执行一次复位（`--reset=both`），把演示写入的预约清掉，避免污染后续 E2E / 截图。

## 七、录制与编码实现要点

- 浏览器：Chromium headless，视口与录屏尺寸均为 1440×900，`locale=zh-CN`、`timezoneId=Asia/Shanghai`。
- 叠加层：`addInitScript` 注入合成光标（墨蓝外环 `#1b3f8f`，跟随 `mousemove` / `mousedown`）与底部字幕条（墨蓝 `rgba(21,26,33,0.92)`、浅字、圆角）；字幕存 `sessionStorage`，跨页面导航不丢。
- 字幕在页面内渲染，而不是用 ffmpeg `drawtext`：避免中文字体路径与转义问题，也保证字幕随分辨率缩放。
- 录制中间不加 `page.waitForTimeout` 以外的等待除非必要；每段结尾用 DOM 断言（如冲突 `.el-alert` 含「冲突」、批量通过 toast）确认操作真的发生，避免「录到了但没生效」。
- GIF：`fps → scale=880:lanczos → split → palettegen(max_colors=128,stats_mode=diff) → paletteuse(bayer) → -loop 0`，超 8MB 自动降档重编。
- MP4：`libx264 -preset medium -crf 23 -pix_fmt yuv420p -movflags +faststart -an`（73 秒 / 1440×900 / 2.9MB；AI 片段 30 秒 / 0.8MB）。
