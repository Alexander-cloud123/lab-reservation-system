# 日历总览页优化升级 —— 任务提示词

> 生成日期：2026-09-12
> 任务性质：日历总览页（学生端 `CalendarOverview.vue`，FullCalendar 6.1.15）视觉与信息层级优化
> 范围边界：仅前端页面改造；不新增接口、不新增依赖、不新增功能点、不改业务逻辑与状态流转（符合《AGENTS.md》约束）

---

## 一、市场调研结论（2026-09 检索，来源见文末）

| 调研方向 | 核心结论 | 来源 |
|---|---|---|
| 日历设计四支柱 | 日历 UI 的成功取决于「布局与导航、视觉层级、交互、可访问性」四支柱；日历是**高密度信息组件**，核心矛盾是「信息完整 vs 视觉清晰」 | Eleken《33 Calendar UI Examples》、Muzli |
| 视觉层级 | 颜色要克制使用，只承担一个语义（分类/紧急度/状态）；建立**三级字体层级**（日期数字大、事件小）；用底色/高亮等视觉线索让用户瞬间定位「今天」 | Eleken（Apple Calendar / Notion 案例） |
| 今日标记 | 主流做法是**轻量标记而非整格涂色**：Apple Calendar 用柔和底色引导视线，不加额外标签；Airbnb 用圆形高亮选中日期 | Eleken（Apple / Airbnb 案例） |
| 事件块形态 | 现代日历（Linear / ClickUp / Notion 风格）事件块普遍采用**左侧色条 + 浅色底 + 深色文字**，替代整块高饱和纯色，信息可扫读、不刺眼 | Eleken、BRICX（微交互与可读性） |
| 状态色彩编码 | 预约/排课场景必须保持**状态色语义一致 + 图例可见 + 不单靠颜色传达**（可访问性要求：色盲用户需图案/文字/图例兜底）；色彩需视觉可区分 | SITE123、Eleken |
| 周末/非本月 | 信息密度管理：周末与跨月日期应**降对比度弱化**，把注意力留给当前月工作日 | Muzli、CSDN 日历组件指南 |
| 交互反馈 | 日期格 hover 应有浅色反馈、事件块 hover 应有微交互（轻微加深/抬升），让用户感知系统响应；动效克制、尊重 `prefers-reduced-motion` | BRICX、frontend-design 技能 |
| 主题化技术 | FullCalendar 6.x 官方支持 CSS 变量（`--fc-*`）整套换肤：`--fc-border-color`、`--fc-button-*`、`--fc-today-bg-color`、`--fc-event-*` 等，零侵入定制 | FullCalendar 官方文档、社区主题实践 |
| 预约场景 UI | 预约类日历「快、清晰、零歧义」优先：干净中性底 + 品牌色突出选中/确认态；大点击区、明确状态反馈 | Mejba《Booking UI Prompt》、SITE123 |

**综合判断**：本项目日历页应在不新增功能的前提下，把 FullCalendar 默认外观升级为「**排课表**」质感——**三级信息层级**（星期表头 → 日期数字 → 事件色块）、**轻量今日标记**、**周末/跨月弱化**、**色条式事件块**，并完全复用项目既有设计 Token（冷纸 + 墨蓝黑 + 深普鲁士蓝，扁平面板、克制动效、无渐变）。

## 二、现状诊断（对照市场趋势）

| 问题 | 现状表现 | 与主流趋势差距 |
|---|---|---|
| P1 事件块是整块纯色 | 4 种状态整块高饱和纯色填充 + 11px 白字，教室名/状态文字被截断（如「B301阶梯教…」） | 主流为「左色条 + 浅色底 + 深色文字」，信息可扫读且不刺眼（Linear/Notion/ClickUp 风格） |
| P1 今日标记过重 | `fc-day-today` 整格浅蓝底，无数字级强调 | 主流为轻量标记（数字圆底/顶部细线 + 柔和底色），Airbnb/Apple 式 |
| P2 日期数字层级弱 | 日期数字与事件同为 12px 级别，无主次；周末、跨月日期与工作日无区分 | 应建立「数字 → 事件」两级字体层级；周末/跨月降对比度管理信息密度 |
| P2 按钮为 FullCalendar 默认 | 顶部 `<` `>` `今天` 沿用组件默认外观，未与 Element Plus 小按钮体系对齐 | 组件按钮应与全站控件视觉统一（白底 + 边框 + 品牌色 hover/active） |
| P2 无 hover 微交互 | 日期格与事件块 hover 无反馈 | 主流均有浅色 hover 反馈，让用户感知可点击（BRICX：microinteractions） |
| P2 状态色传达单一 | 状态只靠色块颜色，图例圆点为方形小色块 | 可访问性要求不单靠颜色：保留图例 + 悬浮详情 + 点击详情弹窗的多通道传达，事件块内保留状态信息通道 |

### 设计要点（全部基于既有 Design Token，无新增色值）

1. **事件块 → 色条式**：状态色从「整块填充」改为「左侧 3px 色条 + 状态浅色底 + 深色文字」（仍为扁平，无渐变）。块内两行：上行等宽数字时段（`08:00-10:00`，10.5px 次要色，`tabular-nums` 防跳动），下行教室名（11px/600 主文字色，超长省略号）。悬浮详情（原生 title）保留完整信息：教室 + 时段 + 状态 + 用途；点击弹窗不变。
2. **状态色语义不变**：待审核 `--brand-warning` / 已通过 `--brand-success` / 已驳回 `--brand-danger` / 已取消 `--brand-info`，与图例、全站状态标签完全一致；浅底用对应 `-light` token。
3. **今日轻量标记**：去掉整格浅蓝底；改为「今日数字品牌色圆底白字 + 单元格顶部 2px 品牌色细线 + 极浅品牌色底」三层轻提示（尊重 Apple/Notion 的 subtle cue 做法）。
4. **日期数字层级**：默认数字 12.5px/600 墨蓝黑；**周末与跨月日期**数字降为占位色（`--text-placeholder`）；跨月事件块降透明度，把注意力留给当月。
5. **星期表头**：浅底（`#f7f9fb`）+ 12px/600 次要色，周六/周日上午字色降为占位色。
6. **顶部按钮品牌化**：通过 `--fc-button-*` 变量把 `<` `>` `今天` 对齐 Element Plus 小按钮（白底、`--border-color` 边框、8px 圆角、hover 品牌浅色底 + 品牌色边框、active 品牌主色底白字）；「今天」禁用态保持当前月可读样式。
7. **hover 微交互**：日期格 hover 极浅品牌底（`--brand-primary-lighter`）；事件块 hover `brightness(0.96)` 微加深 + 1px 轻抬升阴影；均 0.15s 过渡，`prefers-reduced-motion` 全局兜底。
8. **分隔线弱化**：`--fc-border-color` 置为 `--border-color-light`，网格线更轻，符合「扁平面板」语言。
9. **工具栏微调**：图例圆点改圆形（8px 圆点 + 对应状态色），间距与视图切换对齐；其余结构（教室筛选 / 图例 / 月周日切换）与点击行为原样保留。

## 四、硬性约束

1. 唯一需求依据：《需求设计文档.md》2.4 节「预约日历总览页（亮点）」—— FullCalendar 月/周视图切换、预约色块标记、点击日期快速发起预约、悬浮显示详情，**四项能力全部保留，不得增删**。
2. **不新增**后端接口、数据库字段、npm 依赖；**不改**预约冲突检测、状态流转、提交/取消/审核逻辑与接口调用。
3. 复用项目设计 Token（`main.css` 变量）：`--brand-primary: #1e6091`、`--brand-success/-warning/-danger/-info` 及 `-light` 系列、`--border-color-light`、`--bg-page`、圆角分级、扁平阴影；**禁止**渐变、玻璃拟态、紫色系、默认 Element Plus/FullCalendar 蓝色。
4. 前端规范：方法小驼峰、关键函数加注释；操作 FullCalendar/Element Plus 内部元素必须 `:deep()`；事件块自定义渲染必须用 DOM 节点 + `textContent` 赋值，禁止直接拼 HTML（防 XSS）。
5. 无障碍：状态不单靠颜色传达（图例 + 悬浮详情 + 详情弹窗保留）；键盘焦点可见（全局已兜底）；正文对比度 ≥ 4.5:1；`prefers-reduced-motion` 生效。
6. 交付前必须用 `.agents/skills/avoid-ai-design` 的 detect 模式自检，P0/P1 级 AI 痕迹清零；再跑 `npm run build` 确认通过；并在实机浏览器对比改前/改后截图。

## 五、验收标准

1. 月/周视图切换、点击空白日期快速预约、点击色块查看详情、悬浮显示详情四项功能全部正常（对比改前基线逐一验证）。
2. 事件块呈「左色条 + 浅色底 + 深色文字」形态，4 种状态色与图例、状态标签一致；跨月事件有弱化；教室名超长省略号截断。
3. 今日有「数字圆底 + 顶部细线 + 极浅底」轻量标记；周末/跨月日期数字弱化可见。
4. 顶部 `<` `>` `今天` 按钮与 Element Plus 视觉一致（hover/active 状态齐全）；网格线为浅色。
5. 日期格与事件块 hover 反馈生效；`npm run build` 通过；avoid-ai-design detect 无 P0/P1；无 `javax.*`、无硬编码密钥、无新增依赖、无接口/逻辑改动。
6. 响应式：窄屏下日历无横向溢出（FullCalendar 自适应），工具栏可换行。
