## 二、基线重导与编码修复记录

### 1. 重导基线必须带 `--default-character-set=utf8mb4`

- 现象：重导基线（`docker exec -i mysql < init_db.sql`）后，API 中文筛选失效（`building=信息楼` 返回 0 条，R7 当日为 4 条），`sys_user.name` 读出乱码。
- 根因：未指定字符集时容器内 mysql 客户端按 latin1 解析 UTF-8 字节流，中文被**双重编码**写入（例：张三 HEX=C3A5C2BCC2A0…，正确为 E5BCA0E4B889）。
- 修复：`cmd /c "docker exec -i reservation-mysql mysql --default-character-set=utf8mb4 -uroot -proot reservation < init_db.sql"` → HEX 恢复标准 UTF-8，`building=信息楼` 恢复 total=4，T74 复跑通过。
- **操作前提**：R8 及以后所有基线重导必须带 `--default-character-set=utf8mb4`（本报告所有重导均按此执行）。

### 2. 演示期 PowerShell 中文传参（docker exec）GBK 乱码

- 现象：`UPDATE reservation SET purpose='商业推销活动' WHERE id=13`（PowerShell 直接传中文）写入乱码字节。
- 修复：改用 HEX 传值 `SET purpose=CONVERT(0xE59586E4B89AE68EA8E99480E6B4BBE58AA8 USING utf8mb4)`（startup-guide.md 已记载该注意事项），验证 HEX=E59586E4B89AE68EA8E99480E6B4BBE58AA8 正确。
- 演示脚本/恢复语句已全部采用 ASCII 或 HEX 值。
