# 个人中心优化升级 —— 任务提示词

> 生成日期：2026-09-12
> 任务性质：个人中心（学生端 `Profile.vue`）视觉与信息架构优化
> 范围边界：仅前端页面改造；不新增接口、不新增依赖、不新增功能点、不改业务逻辑（符合《AGENTS.md》约束）

---

## 一、市场调研结论（2026-09 检索，来源见文末）

| 调研方向 | 核心结论 | 来源 |
|---|---|---|
| 个人中心定位 | 个人中心 = 「个人信息 + 功能入口 + 全局操作」的**信息分流页**，设计目标不是展示个性而是**提高效率**；与"个人主页"（展示个性）是两种形态 | 人人都是产品经理《个人中心该怎么画》 |
| 高频低满意度 | 个人中心是日均访问 3.2 次的高频页面，但传统 2D 设计常被吐槽"像 Excel 表格——头像、名字、按钮排在同一平面，没有个性与层次" | 华为开发者《个人中心卡片的空间化升级》 |
| 头部身份区 | 个人信息区是"脸面"，**必须放页面顶部**，优先级最高但面积占比要小；超八成产品采用**头像居左**（符合 F 形浏览习惯）；头部可用主色/浅色块做出"个人名片"感 | 站酷《全面解析APP个人中心设计思路》、人人都是产品经理 |
| 数据概览条 | 强头部下方紧跟 **3–4 个数字统计条**（stats strip），让用户在 2 秒内看到自己的使用概况（社交证明/掌控感） | Gummble《Profile UI Design Patterns》 |
| 功能入口 | 核心高频功能必须**前置为宫格/宫格+列表入口**，3–4 个主要入口首屏可见；"入口多、层级深、屏效低"是个人中心三大痛点 | 百度APP个人中心重构案例、墨刀 |
| 设置下沉 | 高频内容置顶、低频高风险操作（改密码/安全设置）**下沉到页面底部**并分组；敏感操作保持二次确认；设置分组是通用惯例（Account / Notifications / Security） | Eleken、Gummble |
| 2025–2026 UI 趋势 | 单一承诺主色 + 充足留白 + 分层深度（克制阴影）；可访问性默认（4.5:1 对比、键盘焦点、减少动效）；目的性微交互（保存 → "已保存"反馈） | Colorhero《UI Design Trends 2025》 |
| 校园类系统共性 | 校园个人中心标准结构：**身份卡片（学号/姓名）+ 待办提醒 + 数据统计 + 通知公告 + 高频功能入口**；清爽效率风、数字突出、信任色系 | 学工系统/校园通原型、CSDN 选课系统 |

**综合判断**：本项目个人中心应在不新增功能的前提下，重构为「**身份名片 + 数据概览 + 高频入口 + 通知 + 账户安全**」的五段式结构，把"功能分流"职责做出来，同时保持项目既有设计语言（冷纸 + 墨蓝黑 + 深普鲁士蓝，扁平面板、克制动效）。

## 二、现状诊断（对照市场趋势）

| 问题 | 现状表现 | 与主流趋势差距 |
|---|---|---|
| P1 缺身份名片 | 页面直接从 4 张统计卡开始，无头像+姓名+学号的身份区 | 主流个人中心第一屏必须是身份卡（Gummble：profile header <200px） |
| P1 缺功能分流入口 | 仅有"常用教室"一个入口模块；"我的预约/日历"只能靠顶部导航 | 个人中心作为信息分流页，核心入口必须前置成宫格，3–4 个首屏可见 |
| P2 统计与身份割裂 | 统计卡与用户信息完全分离 | 主流做法是身份下方紧跟 stats strip |
| P2 无页面标题 | 进入页面无"个人中心"标题栏，首屏感知弱 | 全站其他页均有 page-head，页面一致性与定位感不足 |
| P2 设置不分组 | 个人信息与修改密码两张表单并排暴露在中部 | 安全类操作应下沉并归入"账户与安全"分组 |
| P2 无待办感知 | 消息通知为纯列表，无"待审核中"的聚合提示 | 校园类系统普遍提供待办提醒/状态聚合 |

## 三、优化设计（布局方案）

```
┌──────────────────────────────────────────────┐
│ 个人中心                                      │  ← page-head 标题栏
├──────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────┐ │
│ │ [头像] 姓名  [学生]        编辑资料        │ │  ← ① 身份卡
│ │ 学号 2024xxxx · 账号 zhangsan             │ │
│ │ ──分隔线──                               │ │
│ │ 累计预约 │ 本月预约 │ 审核通过率 │ 最近一次 │ │  ← ② 数据概览条
│ └──────────────────────────────────────────┘ │
├──────────────────────────────────────────────┤
│ 快捷功能                                      │  ← ③ 高频入口宫格（4 格）
│ [我的预约] [预约日历] [常用教室] [教室列表]     │
├──────────────────────────────────────────────┤
│ 常用教室（收藏列表 + 空状态引导）               │  ← ④ 收藏区（保留）
├──────────────────────────────────────────────┤
│ 消息通知（未读徽标 + 全部标已读）               │  ← ⑤ 通知区（保留逻辑）
├──────────────────────────────────────────────┤
│ 账户与安全                                    │  ← ⑥ 设置区（下沉）
│ 左：个人信息表单  右：修改密码表单              │
└──────────────────────────────────────────────┘
```

### 设计要点

1. **身份卡**：头像（沿用姓名末位占位，56px）+ 姓名（18px/700）+ 角色徽标（学生）；第二行学号 · 登录账号（13px 次要色）；右侧"编辑资料"文本按钮 → 平滑滚动到账户与安全区；卡片背景用 `--brand-primary-lighter` 浅色块 + 1px 边框，扁平、无渐变、无辉光。
2. **数据概览条**：4 个统计并入身份卡下半区（分隔线 + 4 列），保留现有字段与空值兜底（`?? 0` / 暂无）。
3. **快捷功能宫格**：4 格（我的预约/预约日历/常用教室/教室列表），图标 + 名称 + 一句用户视角副文案；hover 仅边框/底色变化；点击跳转已有路由（`/student/my-reservations`、`/student/calendar`、`/student/home`，常用教室滚动到收藏区）。
4. **常用教室 / 消息通知**：保留现有数据逻辑与已读机制，仅统一视觉；空状态保留操作引导。
5. **账户与安全**：两张表单下沉至页面底部同一卡片组（左右分栏），保留全部校验规则、二次确认、保存反馈；标题"账户与安全" + 一行说明文案。
6. **文案**：用户视角命名、主动语态；错误不道歉；空状态给操作引导（沿用 frontend-design 写作原则）。

## 四、硬性约束

1. 唯一需求依据：《需求设计文档.md》2.4 节个人中心页 —— 五个功能点（数据概览/常用教室/消息通知/个人信息/修改密码）**全部保留，不得增删**。
2. **不新增**后端接口、数据库字段、npm 依赖；**不改**业务逻辑、状态流转、校验规则。
3. 复用项目设计 Token（`main.css` 变量）：`--brand-primary: #1e6091`、`--bg-page: #f3f5f7`、圆角分级、扁平阴影；禁止渐变、玻璃拟态、紫色系、默认 Element Plus 蓝色。
4. 前端规范：组件名大驼峰、方法小驼峰、函数加注释；操作 Element Plus 内部元素必须 `:deep()`；关键交互保留二次确认。
5. 无障碍：键盘焦点可见（全局已兜底）、`prefers-reduced-motion` 生效（滚动跳转也要判断）；正文对比度 ≥ 4.5:1。
6. 交付前必须用 `.agents/skills/avoid-ai-design` 的 detect 模式自检，P0/P1 级 AI 痕迹清零；再跑 `npm run build` 确认通过。

---

## 五、验收标准

1. 五段式结构完整呈现：身份卡 + 数据概览 + 快捷宫格 + 收藏 + 通知 + 账户与安全；页面有"个人中心"标题栏。
2. 原有五功能点全部可用：统计加载、收藏跳转、通知已读/全部已读、资料保存、密码修改（含二次确认与重新登录）。
3. 快捷宫格 4 个入口均跳转到正确路由（我的预约/日历总览/教室列表/收藏区）。
4. `npm run build` 通过；avoid-ai-design detect 无 P0/P1；无 `javax.*`、无硬编码密钥、无新增依赖。
5. 响应式：窄屏下宫格与表单自动降为单列，无横向溢出。

## 七、二期优化附录（2026-09-12 追加）

> 反馈："账户与安全出现的方式太传统和老套"。按 2025–2026 主流 App 设置形态重新设计，范围仍仅 `Profile.vue`，功能点与接口零变更。

**改动**：
1. **页面标题 → 时间感知问候**："下午好/晚上好，张三"（个性化首屏，无表情符号）。
2. **账户与安全 → 分组设置列表**（替代并排双表单，类 iOS/主流 App 设置）：
   - 分组「个人资料」：列表行（图标 + 标签 + 当前值 + 箭头），登录账号/学号只读；姓名/邮箱/手机号可点 → 打开**编辑资料弹窗**（预填当前值，保留原校验规则，保存后同步用户信息并关闭）。
   - 分组「账号安全」：修改密码行 → 打开**修改密码弹窗**（原/新/确认密码，保留校验、二次确认、改后重新登录）。
   - 未填写的邮箱/手机号以灰色"未填写"呈现；弹窗打开时清除历史校验痕迹。
3. **消息通知 → 图标化消息流**：每条消息左侧类型图标色块（待审核=Clock 黄 / 已通过=CircleCheck 绿 / 已驳回=CircleClose 红 / 即将开始=AlarmClock 蓝），替代小标签，保留未读红点与全部已读。
4. **快捷功能宫格**：hover 增加轻抬升阴影（`--shadow-hover`），保持扁平。
5. **身份卡"编辑资料"按钮**：直接打开编辑弹窗（一步直达，减少操作层级）。

**验证**：`npm run build` 通过；实机 Chrome 重新登录后五段结构、双弹窗（打开/预填/取消）、数据加载（4/4/66.7%、收藏 2、通知 5 未读）全部正常。
